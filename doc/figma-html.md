# Figma → HTML 구현 지침 (HTML만)

Figma 프레임의 내용과 구조를 **완성된 시맨틱 HTML**로 만듭니다. 스타일은 이후 [figma-html-css.md](figma-html-css.md)로 작성하므로, 이 단계의 목표는 "CSS 없이도 내용과 읽기 순서가 맞는 HTML"과 "CSS 작성자가 바로 쓸 수 있는 클래스·인계표"입니다.

먼저 [figma-guide.md](figma-guide.md)의 공통 규칙을 읽고 따릅니다.

## 범위

| 구분 | 대상 |
| --- | --- |
| 수정 | `src/pages/index.html`, `src/images/`(자산 추가), 필요하면 `src/partials/` |
| 수정 금지 | `src/scss/**`, `src/js/**`, `dist/` |
| 사용 금지 | 인라인 `style`, `<style>` 요소 |

상호작용(메뉴 열기 등)에 JavaScript가 필요하면 마크업과 ARIA 초기값만 작성하고 보고서에 적습니다.

## 절차

1. **준비**: 공통 §1(시작 전 확인), §2(MCP 호출), §3(자산)을 수행합니다.
2. **콘텐츠 목록 작성**: 마크업 전에 프레임별로 아래 항목을 정리합니다.
   - 모든 텍스트
   - 이미지와 아이콘, 그리고 각각이 정보용인지 장식용인지
   - 인터랙티브 요소: 링크인지 버튼인지, 목적지, Figma에 그려진 상태(hover 등)
   - 모바일과 데스크톱의 차이: 내용이 다르거나, 순서가 다르거나, 한쪽에만 있는 요소
3. **읽기 순서 결정**: DOM 순서는 내용을 읽는 순서를 따릅니다. 화면에서 배치 순서만 다른 경우는 CSS 단계에서 처리하도록 인계표에 적습니다. 한쪽 화면에만 있는 요소도 HTML에 넣고 인계표에 표시합니다.
4. **마크업**: 공통 §4(HTML 규칙), §5(Auto Layout 대응)를 따릅니다.
   - 모든 요소에 역할 기준의 `c-` 클래스를 붙입니다. CSS 단계에서 클래스를 다시 설계하지 않도록 합니다.
   - Auto Layout 방향에 맞춰 `l-` 클래스를 붙입니다. gap이 `data-*` 프리셋과 정확히 같을 때만 프리셋을 씁니다. 다르면 프리셋 없이 두고 인계표에 Figma 값을 적습니다.
   - **gulp `@@` 구문과 Prettier**: 시작 태그의 속성 자리(따옴표 밖)에 `@@if`를 쓰면, 그 요소 바로 위 줄에 `<!-- prettier-ignore -->`를 붙입니다. Prettier는 따옴표 밖의 `@@if (조건) { 속성}`을 HTML 속성으로 읽어 `@@if`, `(context.selected`, `!=""`처럼 쪼개기 때문입니다. 그러면 gulp 구문이 깨집니다.

     ```html
     <!-- prettier-ignore -->
     <div class="c-crew__panel" id="crew-panel-pilot" role="tabpanel" aria-labelledby="crew-tab-pilot" tabindex="0"@@if (context.selected !== 'pilot') { hidden}>
     ```

     - 붙이지 않아도 되는 곳: 속성값 따옴표 **안**의 `@@if`(예: `aria-selected="@@if (…) {true}…"`)와 페이지의 `@@include(...)` 줄. Prettier가 들여쓰기만 바꾸고 구문은 그대로 둡니다.
     - `<!-- prettier-ignore-attribute -->`로는 막히지 않습니다. 속성을 읽는 단계에서 이미 쪼개지기 때문입니다.
     - `prettier-ignore`는 요소 전체(자식 포함)를 포맷에서 뺍니다. 주석은 빌드된 HTML에도 남지만, 화면과 동작에는 영향이 없습니다.
     - Prettier 설정 파일(`.prettierrc.json`, `.prettierignore`)로는 "`@@`가 있는 줄만 제외"할 수 없어 이 주석 방식을 씁니다.
5. **스타일 인계표 작성**: 보고서에 클래스별 Figma 값을 표로 남깁니다.

   | 클래스 | Figma 노드 | 크기·간격·패딩 | 글꼴(크기/굵기/줄 간격) | 색 | 상태 | 반응형 차이 |
   | --- | --- | --- | --- | --- | --- | --- |

   Figma 변수 이름이 있으면 값과 함께 적습니다(예: `Blue/400 #8BACD9`).
6. **검증**: 아래 항목을 확인하고 보고합니다.

## 검증

- 미리보기: 공통 §6의 방법 A를 씁니다. 화면에는 기존 SCSS가 적용되므로 **시각적 일치는 판단하지 않습니다**.
- 내용 대조: 2단계 콘텐츠 목록과 HTML을 비교해 누락·추가가 없는지 확인합니다.
- 자산: 모든 `src`가 `src/images`의 실제 파일인지, localhost 주소가 없는지 확인합니다.
- 범위: `git diff --stat`으로 `src/scss`, `src/js` 변경이 없는지 확인합니다.
- 브라우저(Chromium): 이미지 로드, 탭 순서, 제목 계층, 링크·버튼 이름을 확인합니다.

## 완료 기준

- [ ] Figma의 모든 텍스트·이미지·인터랙티브 요소가 HTML에 있고, 없는 요소를 추가하지 않았다
- [ ] 랜드마크(`main`), 제목 계층, `lang`, `title`이 맞다
- [ ] 링크와 버튼을 목적에 맞게 구분했고, 목적지를 모르는 링크는 보고서에 적었다
- [ ] 정보 이미지에는 설명 `alt`, 장식 이미지에는 `alt=""`를 넣었다
- [ ] 자산이 `icon-*`/`image-*` 이름 규칙을 따르고, 중복 파일과 localhost 주소가 없다
- [ ] 모든 요소에 BEM `c-` 클래스와 알맞은 `l-` 클래스가 있고, ID는 연결용으로만 썼다
- [ ] 인라인 스타일이 없고, `src/scss`·`src/js`를 수정하지 않았다
- [ ] 따옴표 밖 `@@if`가 있는 요소마다 바로 위에 `<!-- prettier-ignore -->`가 있다
- [ ] 보고서에 스타일 인계표, placeholder, 미검증 항목을 적었다
