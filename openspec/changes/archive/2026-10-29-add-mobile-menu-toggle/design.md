# Design

## Context

- `src/js/main.js`는 비어 있고, 12개 페이지 어디에도 `<script>`가 없다. 공통 `<head>`는 `src/partials/head.html` 하나에서 `@@include`로 생성된다.
- 상태 스타일은 이전 변경(`style-site-header`)에서 이미 만들어 두었다. 헤더 루트 `.c-site-header`의 클래스로 상태를 표현하며, 모든 규칙이 `mq-below('tablet')`(`width < 48em`) 안에 있어 768px 이상에서는 효과가 없다.
  - `.is-enhanced`: 토글 표시, `.c-nav`를 `display: none`으로 숨김
  - `.is-menu-open`: 오른쪽 고정 패널, 세로 목록, 닫기 아이콘 표시
- 토글 마크업: `button.c-nav-toggle[aria-expanded="false"][aria-controls="primary-navigation"]`, 이름은 내부 `span.u-sr-only`의 "Open menu" 텍스트다.
- 빌드의 정적 복사(`src/{js,images,fonts}/**/*`)가 이미 `js/main.js`를 결과물로 복사한다.
- 저장소 규칙상 `dist`를 지우는 `npm run build`·`npm run dev`는 실행하지 않는다. 검증은 이전 변경과 같이 스크래치 폴더 미리보기 빌드로 한다.

## Goals / Non-Goals

**Goals:**
- 스크립트가 있을 때만 햄버거 메뉴로 바뀌는 점진적 향상(스크립트 없을 때의 대체 배치 유지)
- 상태 클래스, `aria-expanded`, 버튼 이름, 아이콘이 항상 같은 상태를 가리키도록 한 곳에서 갱신
- Escape·바깥 클릭·분기점 전환에서도 상태가 어긋나지 않음

**Non-Goals:**
- SCSS·헤더 HTML 구조 변경, 열림·닫힘 애니메이션
- 포커스 가두기, 배경 `inert`, 본문 스크롤 잠금(모달로 만들지 않음 — 아래 결정 4)
- 탭 위젯(`content-tabs`) 등 다른 스크립트 기능
- proposal의 "후속 change로 넘기는 항목"(가려진 포커스 대응, 패널 넘침, 버튼 이름 정책, 고대비·포커스 표시·대비 점검). 이번에는 아래 결정대로 구현하고, 후속 change에서 바뀔 수 있다.

## Decisions

### 1. `<head>`에서 `defer`로 불러온다
`src/partials/head.html`의 스타일시트 다음에 `<script src="./js/main.js" defer></script>`를 넣는다. 원본 한 곳만 바꾸면 12개 페이지에 반영되고, `defer`라 파싱을 막지 않으면서 실행 시점에는 헤더 DOM이 존재한다.
- 대안: 각 페이지 `</body>` 앞에 넣기 → 12개 파일 수정이 필요하고 "공통 마크업 단일 원본" 요구사항과 어긋나 제외.
- 대안: `type="module"` → 동작은 같지만 `file://`로 열면 CORS로 막혀 미리보기 확인이 어려워 제외.

### 2. 모든 상태를 하나의 함수로 갱신한다
`setOpen(isOpen)` 하나가 `.is-menu-open` 토글, `aria-expanded`, `u-sr-only` 텍스트("Open menu"/"Close menu")를 함께 바꾼다. 클릭·Escape·바깥 클릭·분기점 처리 모두 이 함수만 호출한다. 아이콘 전환은 기존 SCSS가 `.is-menu-open`으로 처리하므로 스크립트가 건드리지 않는다.
- 버튼 이름은 `aria-label`을 새로 추가하지 않고 기존 숨김 텍스트를 바꾼다. 마크업 계약(숨긴 텍스트로 된 이름)을 유지하기 위해서다.
- 요소를 찾지 못하면(헤더·토글·목록 중 하나라도 없음) 아무것도 하지 않고 종료해 `.is-enhanced`도 붙이지 않는다. 이 경우 대체 배치가 남는다.

### 3. 분기점은 `matchMedia('(width < 48em)')`로 감지한다
SCSS `mq-below('tablet')`와 같은 식을 써서 CSS와 스크립트의 분기점이 일치한다(루트 글꼴 크기를 키웠을 때도 같이 움직임). `change` 이벤트에서 더 이상 일치하지 않으면 `setOpen(false)`를 호출한다.
- 대안: `resize` 이벤트 + `innerWidth < 768` → 매 프레임 실행되고 px 기준이라 em 분기점과 어긋날 수 있어 제외.
- 범위 미디어 쿼리 문법(`width <`)은 이미 SCSS 출력에서 쓰고 있으므로 같은 브라우저 지원 범위로 본다.

### 4. 비모달 공개(disclosure) 패턴을 쓴다
패널은 화면 오른쪽 254px만 덮고 배경을 어둡게 하지 않으며(Figma 120:2725), 본문이 계속 보인다. 그래서 대화상자처럼 포커스를 가두지 않고 버튼 + `aria-expanded`의 공개 패턴으로 둔다. DOM 순서상 토글 다음이 목록이므로 열고 Tab을 누르면 첫 링크로 간다.
- 보조 닫기: `document`의 `keydown`에서 열림 상태의 Escape → 닫고 토글에 포커스. `document`의 `click`에서 대상이 헤더 밖이면 닫는다. 패널(`.c-nav`)과 토글은 헤더 안에 있으므로 패널 빈 곳 클릭은 열림을 유지한다.
- 대안: `<dialog>`/모달 + `inert` → 마크업과 기존 spec 변경이 필요하고 디자인 의도(본문이 보이는 패널)와 맞지 않아 제외.

### 5. 활성화 클래스는 스크립트 실행 즉시 붙인다
`defer` 실행 시점에 바로 `.is-enhanced`를 추가한다. 대체 배치와 햄버거 배치의 높이가 달라 첫 그리기 전에 실행되지 않으면 순간적인 배치 변화가 생길 수 있다(위험 참조).

### 6. 코드 형식
의존성 없는 일반 스크립트로 작성하고, 전역 변수를 남기지 않도록 블록 스코프로 감싼다. 프로젝트 Prettier 설정(작은따옴표)을 따른다. 주석은 기존 SCSS처럼 한국어로 "관계·제한·전환" 수준만 적는다.

## Risks / Trade-offs

- [스크립트 실행 전 첫 그리기로 모바일에서 링크 목록이 잠깐 보였다가 숨겨짐] → `defer`는 보통 첫 그리기 전후로 실행된다. 미리보기에서 느린 네트워크 조건으로 확인하고, 눈에 띄면 `<head>` 인라인으로 `<html>`에 클래스를 먼저 붙이는 방안을 후속으로 검토한다(이번 범위 밖).
- [포커스를 가두지 않아 열린 상태에서 Tab이 패널을 벗어나 본문으로 이동하고, 패널 뒤에 가려질 수 있음] → 이번 범위에서는 그대로 두고 후속 change에서 대응 방식을 정한다.
- [바깥 클릭 리스너가 항상 등록됨] → 닫힘 상태에서는 즉시 반환하므로 비용이 작다.
- [열린 패널이 화면 높이 전체를 덮어 가로 모드·확대 시 링크가 잘릴 수 있음] → 패널 스타일 변경은 후속 change에서 다룬다.

## Migration Plan

배포 단계 없음. 되돌리려면 `head.html`의 `<script>` 한 줄을 지우면 대체 배치로 돌아간다.
